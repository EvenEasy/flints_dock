# Read-only desktop backend

This directory contains a Tauri 2 Rust adapter and a TypeScript IPC boundary, not a frontend application. The existing scanner, models, pricing, classification and transaction use cases remain in `crates/core`; the desktop registers only `analyze_wallet`. CLI swap/cleanup functionality remains available in `apps/cli`.

## Backend configuration

Clients are created once at startup and shared through managed `AppState`:

- `DOCK_FLINTS_RPC_URL`: default `https://api.mainnet.solana.com`.
- `DOCK_FLINTS_RPC_TIMEOUT_SECONDS`: default `30`, accepted range `1..=300`.
- `JUPITER_API_KEY`: optional, same existing Price API integration as the CLI. Without it, balances remain available and price status reports unavailable. `noPrices: true` disables price lookup.

The desktop API accepts only a public wallet address. No signing input, swap, burn, close, shell, filesystem or process commands/plugins are exposed. The local `main` window is granted only `allow-analyze-wallet`; application command permissions are generated by `build.rs`.

## IPC

```ts
import { analyzeWallet } from './frontend-contract';

const wallet = await analyzeWallet({
  walletAddress: 'YOUR_SOLANA_PUBLIC_KEY',
  selection: { balance: true, tokens: true, nfts: true },
  noPrices: true,
});
```

Selectors match current CLI semantics: `balance`, `tokens`, `allTokens`, `nfts`, `cnfts`, and `all`. Omitted/empty selection expands to all semantic categories, with `allTokens` remaining opt-in. `tokens` preserves the core's aggregated fungible **and unclassified** token view; `allTokens` preserves the per-account view, including NFT-backed accounts. NFT results retain independent classic/programmable and MPL Core statuses. cNFTs remain unsupported without a historical index, with `items: null`.

Unselected category DTOs are `null`. Selected failed/unsupported lists have `items: null`; successful empty lists have `items: []`. Partial reads keep available results and diagnostics. Raw inventory and account summaries are also null when account discovery failed; failed mint enrichment has null mint data. `hasUsableResults` follows the existing core's success semantics; check each scanner/category status. Scanner map keys remain the existing core diagnostic names (for example `native_sol`, `core_asset_v1`, `compressed_nfts`). Malformed or unknown DTO fields reject as `invalid_request`; invalid wallet addresses reject as `invalid_wallet_address`. Both use `{code, message, details}`; RPC/pricing failures stay in scanner statuses rather than discarding the snapshot.

All raw amounts, lamports, mint supply, block IDs and byte lengths are decimal strings. SOL/token decimal balances retain their full string precision. Decimals and inventory counts fit JS numbers; USD estimates remain approximate numbers. Optional unavailable fields are `null`. Token-2022 extension **names** are exposed; untyped extension/account JSON is deliberately omitted from IPC to avoid leaking precision-unsafe numbers. Core models remain unchanged.

## Integrating React later

1. Create your frontend separately under `apps/app` and add `@tauri-apps/api` version 2 there.
2. Move/adapt `frontend-contract` to `src/shared/api`; keep all direct `invoke()` calls in that boundary.
3. Set `build.devUrl`, `build.frontendDist`, `beforeDevCommand` and `beforeBuildCommand` in `src-tauri/tauri.conf.json` for your actual frontend toolchain.
4. Adjust CSP only for the frontend's real asset/development needs. Enable bundling and replace the minimal required build icon with your application icons when packaging.
5. Run the Tauri CLI from `apps/app` (or use `cargo run -p dock-flints-app` for the Rust executable).

`frontendDist: []` intentionally embeds no frontend files and allows backend-only compilation, including the `custom-protocol` feature. Running the current executable does not display a working UI. No placeholder HTML or React project is generated.

## Validation

From the workspace root:

```sh
cargo fmt --all
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets --all-features
```

Linux builds require the Tauri GTK/WebKit development libraries. The existing mocked RPC/HTTP regression suite and desktop DTO tests submit no on-chain transactions.
